## 一、本轮发现并修复的真实缺陷

工程里 U1 的实例属性写的是

```
{PROGRAM=..\keil_firmware\output\StickInsert.hex}
```

而 `keil_firmware\output\` 这个目录**在盘上根本不存在**——Keil 工程 `control.uvprojx` 的实际输出是
`<OutputDirectory>.\</OutputDirectory>` + `<OutputName>control</OutputName>`，即
`keil_firmware\control.hex`（4810 B / MD5 `17ab2aeaa907c0504321c7deb6275852`）。
也就是说：**此前这份 Proteus 工程即使按下 Play，单片机里也没有程序**，这解释了历轮"仿真没反应"。

处理方式（保持单一数据源，不在盘上造假目录）：在 Proteus 会话里把 U1 的
`Program File` 改成 `..\keil_firmware\control.hex` 并保存工程。

改前备份：`StickInsert_ref_copy.pdsprj.bak_before_simfix_20261103_0825`（MD5 `f8862074fc66efc080069cb19f05b3bd`，14,125 B）
改后落盘：MD5 `69427329e373138df36956aecc52a43a`，14,109 B，直读 zip 内 `ROOT.DSN` 复核：

```
{PROGRAM=..\keil_firmware\control.hex}     ← 已生效
{CLOCK=11.0592M}                            ← 实例晶振频率正确（另一条 12MHz 是库默认值）
```

## 三、仍未完成（诚实口径）

1. **P1 端口随仿真时间的逐时刻表没取全**。Proteus 的 8051 SFR 工具窗口只在仿真存活期间存在，且会被仿真日志窗口压住；把它挪位后 Proteus 不重绘（裁到空白画布），不挪则被遮挡，跑起来后窗口还会自行消失。已取得的只是 t≈0 的一张 SFR 快照 + 仿真时钟推进序列。
2. **看板级证据（LED 亮灭顺序）没有**：工程里根本没有连线，要出这个证据必须先在画布上摆 3 颗 LED + 3 个电阻 + 接地端并连线。

## 四、下一轮的可复现配方（把坑都标出来了）

```text
坐标口径：本机 125% 缩放。win32 的 GetWindowRect / SetCursorPos 是 LOGICAL，
          ImageGrab 截图是 PHYSICAL，换算系数 1.25（截图像素 ÷ 1.25 = 点击坐标）。
1) 冷启动：PDS.EXE "<工程.pdsprj>"（C:\Program Files (x86)\Labcenter Electronics\Proteus 8 Professional\BIN）
2) 启动仿真：PostMessage(主窗口, WM_COMMAND, 0x0233) —— 此时是 PAUSED at t≈0，正好留出布置窗口的时间
3) 开 SFR：菜单 调试(D) → 8051 CPU → 2. SFR Memory - U1（菜单项是 owner-draw，GetMenuItemID 取不到 id，只能点）
4) 先把仿真日志窗口关掉/挪开，再截图 SFR；不要对 SFR 窗口做 SetWindowPos（会不重绘）
5) 运行：SetForegroundWindow(主窗口) 后发 F12（工具栏 ▶ 按钮实测行为相反，别用）
6) 采样：每帧重新读 SFR 的 GetWindowRect 再裁
7) 停止：Shift+Pause
```

# 参数口径分层说明（v17 验证基线 / SW v2 交付基准）

2026-11-10 整理。**本文件只做登记与说明，不改动任何既有源码、固件、报告或交付件的数值。**

## 1. 为什么盘上会同时存在两组时序数字

这不是错误，而是两条不同用途的基线：

| 层 | 用途 | 参数 | 代表文件 |
|---|---|---|---|
| **v17 归档 · 引脚级验证基线** | 验 8051 三路输出依次导通、急停全灭告警、UART 状态帧；服务于 Proteus 仿真与 hex | 启动 250/125/0 ms、`SYNC_MS 650`、全到位判定 650 ms；注释中有 30/45/60 mm 早期行程 | `keil_firmware\main.c`、`control.hex`(4,810 B / `17ab2ae9…`)、Proteus 正式件、`doc\仿真验证报告.md`、`仿真验证输出.txt`、`固件设计文档.md`、`SI-CLOSE-001_结项报告.md`、`需求规格说明书.md`、`用户操作手册.md`、`演示视频分镜脚本.md`、`LED指示灯实测时序.svg` |
| **SW v2 · 机械动作基准** | 装配模型实测几何决定的最终动作节拍；**对外唯一口径** | 统一 30 mm、初始位 72 mm、错峰 0/125/250 ms、单缸 200 ms、到位 200/325/450 ms、保持 500 ms、复位 350 ms、仿真 0–1300 ms | `13_演示视频\参数对齐_SWv2_统一口径.md`、`matlab\stick_insert_simulation.m`、`qt_gui\cylindercontrol.cpp`、逐帧动画、字幕与 PPT |

## 2. 依据：基准文件自己就写了「零改」

`参数对齐_SWv2_统一口径.md` 第 6 节明确：`qt_gui\host_pc\*`、**`keil_firmware\*`**、Proteus 正式件、AD v19 2D 交付件、`v2.SLDASM` 与 13 个 `.SLDPRT` **一律零改**；v2 对齐只作用于 MATLAB / Qt / 动画 / 字幕 / PPT。
因此本轮**不去改归档文档里的 650 ms / 30·45·60 mm**：只改文字而 `control.hex` 的实际行为不变，会制造「源码与固件已经一致」的假象，比保留分层更糟。

## 3. 对外与面试口径

- 简历、作品集、PPT、汇报、面试口述：一律以 **SW v2 统一口径**为准，不出现 650 ms 同时到位 / 时间差 0 ms / 30·45·60 mm。
- 不带归档固件源码和 v17 旧报告当面试材料。
- 若被追问「固件里写 650 ms，和你说的 450 ms 对不上」：按**分层**解释（引脚级验证基线 vs 机械动作基准），说明项目有统一口径文件约束对外表述、归档件零改，并说明真机落地时会另起一版按 v2 重编固件、重跑 Proteus、更新基线，不覆盖归档件。

## 4. 后续真机落地时的正确做法（不在本轮执行）

1. 另起一版固件（新文件名），按 v2 参数重编并更新 hex 基线；
2. 用新 hex 重跑 Proteus，重新出引脚时序判读图；
3. 接 SQ1~SQ3 到位开关做闭环，多循环记录实际到位时刻，看均值与离散后反标参数；
4. 参数固化到参数表与点检 SOP，加超时告警，改动留痕；
5. 归档版 `main.c` / `control.hex` / 旧报告**保持原样**，作为版本历史保留。

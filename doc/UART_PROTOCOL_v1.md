## 三棒签插签设备 · 8051 ↔ PC UART 字节协议 v1.0（R1 锁定版）

状态：**已锁定**，R2（AD 重画）/ R3（Proteus）/ R4（上位机）/ R5（监控看板）直接引用本文，不得各自改字段。
版本：`PROTO_VER = 1`（帧内不带版本号；如需破坏性变更，升 TYPE 段而非改字段）。
生成时间：2026-10-30。所有示例帧的校验字节由脚本实算并做过失配负例测试，非手推。

### 1. 物理层

| 项 | 值 |
|---|---|
| 波特率 | 9600 bps |
| 数据格式 | 8N1（8 数据位 / 无校验 / 1 停止位），每字节线上占 10 bit |
| 晶振 | 11.0592 MHz（9600 无定时误差） |
| MCU 引脚 | P3.0 = RXD，P3.1 = TXD（硬件 UART，不用软件串口） |
| 电平/桥接 | TTL → USB，CH340 或 CP2102 |
| 线序 | 桥接芯片 TXD → MCU P3.0(RXD)，桥接 RXD ← MCU P3.1(TXD)，共地 |

### 2. 帧封装

```
AA 55 | LEN | TYPE | PAYLOAD[LEN] | SUM
 └头┘   └1┘  └1┘   └── LEN 字节 ──  └1┘
```

- **帧头**固定 `0xAA 0x55`（先 AA 后 55）。
- **LEN** = PAYLOAD 字节数，**不含**头、LEN、TYPE、SUM。合法范围 `1..15`；`0` 或 `>15` 一律判为非法帧。
- **TYPE** 见 §3。
- **SUM** = `(LEN + TYPE + PAYLOAD 全部字节) & 0xFF`，即低 8 位累加和；**帧头不计入**。
- **不使用字节填充**：`AA 55` 可以合法出现在 PAYLOAD 中，解析以 LEN 为准。
- 最大帧长 = 2 + 1 + 1 + 15 + 1 = **20 字节**。

### 3. TYPE 分配

| TYPE | 方向 | 名称 | 周期/触发 |
|---|---|---|---|
| `0x01` | 上行 MCU→PC | 状态帧 | 周期 100 ms（10 Hz） |
| `0x02` | 上行 | 事件帧 | 边沿触发，即时 |
| `0x03` | 上行 | 命令应答帧 | 收到每条命令帧后必发 1 条 |
| `0x81` | 下行 PC→MCU | 命令帧 | 按需 |
| `0x04`,`0x05` | 上行 | 保留 | — |
| `0x82`–`0x8F` | 下行 | 保留 | — |

方向约定：**`TYPE & 0x80 == 0` 为上行，`!= 0` 为下行**。任一端收到方向与自身不符的帧，按校验失败处理（丢弃并重找帧头）。

### 4. 上行 0x01 状态帧（LEN = 14）

小端（低字节在前）。

| 偏移 | 字段 | 宽度 | 类型 | 含义 |
|---|---|---|---|---|
| 0 | SEQ | 1 | uint8 | 帧序号，0→255 循环，用于丢帧/重复检测 |
| 1 | MODE | 1 | uint8 | 0=IDLE 停机, 1=RUNNING 运行, 2=ESTOP 急停, 3=FAULT 告警 |
| 2 | DIO | 2 | uint16 | 数字量位图，见下表 |
| 4 | CNT | 4 | uint32 | 累计插签成功次数 |
| 8 | CYC | 2 | uint16 | 最近一次循环节拍，单位 ms |
| 10 | TMP | 2 | int16 | 温度，单位 **0.1 ℃**（251 = 25.1 ℃）；**未接传感器 = 0x7FFF** |
| 12 | PRS | 2 | uint16 | 气压，单位 **0.1 kPa**（1013 = 101.3 kPa）；**未接传感器 = 0xFFFF** |

DIO 位定义（b0 为 uint16 最低位）：

| bit | 信号 | 有效电平 / 归一规则 |
|---|---|---|
| b0 | YV1 短缸(30mm) | 1=通电 |
| b1 | YV2 中缸(45mm) | 1=通电 |
| b2 | YV3 长缸(60mm) | 1=通电 |
| b3 | SQ1 到位 | 1=到位 |
| b4 | SQ2 到位 | 1=到位 |
| b5 | SQ3 到位 | 1=到位 |
| b6 | SB1 急停 | **1=急停触发**（固件内对 P2.3 常闭取反后上报） |
| b7 | LED_RUN 绿灯 | 1=亮 |
| b8 | LED_ALARM 红灯 | 1=亮 |
| b9–b15 | 保留 | 固件发 0，上位机必须忽略 |

> 归一说明：SB1 硬件为常闭、急停按下时 P2.3 读 0；**取反在固件内完成**，上位机与监控只见"1=急停触发"，与硬件极性彻底解耦。
> 哨兵说明：温度/气压传感器型号未定（纠正版 §0.7），故必须先锁哨兵值——`0x7FFF` / `0xFFFF` 表示"无数据"，上位机/看板**不得**把 0 当作 0 ℃ 或 0 kPa 显示。

### 5. 上行 0x02 事件帧（LEN = 6）

| 偏移 | 字段 | 宽度 | 类型 | 含义 |
|---|---|---|---|---|
| 0 | EVT | 1 | uint8 | 事件码 |
| 1 | SEQ | 4 | uint32 | 事件全局序号，单调递增，用于日志去重与排序 |
| 5 | PAR | 1 | uint8 | 附加参数，无意义时发 0 |

事件码：`0x01` 急停触发（PAR=触发时 DIO 低 8 位）｜`0x02` 到位超时（PAR=超时的缸号 1/2/3）｜`0x03` 连续失败超限（PAR=连续失败次数）｜`0x04` 告警（PAR=告警子码）｜`0x05` 复位完成（PAR=0，上电或收到复位命令后必发）。其余保留。

### 6. 下行 0x81 命令帧（LEN = 3）

| 偏移 | 字段 | 宽度 | 类型 | 含义 |
|---|---|---|---|---|
| 0 | CMD | 1 | uint8 | 命令码 |
| 1 | PARAM | 2 | uint16 | 参数，无参数命令发 0x0000 |

命令码：`0x01` 启动｜`0x02` 停止｜`0x03` 复位（清 CNT 与故障态，回到 IDLE）｜`0x04` 参数下装（PARAM = 到位节拍阈值，单位 ms）。其余保留，收到未定义 CMD 必须回 NAK。

### 7. 上行 0x03 命令应答帧（LEN = 2）

| 偏移 | 字段 | 宽度 | 含义 |
|---|---|---|---|
| 0 | CMD | 1 | 被应答的命令码（原样回显） |
| 1 | RESULT | 1 | 0x00=已执行, 0x01=命令无效/未定义, 0x02=当前状态不允许（如急停中收到"启动"）, 0x03=参数越界 |

每条下行命令**必须**得到一条应答帧；上位机 100 ms 内未收到应答可重发，重发按 CMD+PARAM 幂等处理。

### 8. 示例字节流（脚本实算，SUM 已自洽校验）

| 帧 | 语义 | 字节流 |
|---|---|---|
| 状态帧 | SEQ=7, MODE=RUNNING, YV1+SQ1+RUN_LED 有效, CNT=1234, CYC=620ms, 25.1℃, 101.3kPa | `AA 55 0E 01 07 01 89 00 D2 04 00 00 6C 02 FB 00 F5 03 D7` |
| 事件帧 | 急停触发, EVTSEQ=1234, PAR=0 | `AA 55 06 02 01 D2 04 00 00 00 DF` |
| 命令帧 | 参数下装, 节拍阈值 = 800 ms | `AA 55 03 81 04 20 03 AB` |
| 应答帧 | 命令 0x04 已执行 | `AA 55 02 03 04 00 09` |
| 状态帧(哨兵) | 温度/气压未接 | `AA 55 0E 01 00 00 00 00 00 00 00 00 00 00 FF 7F FF FF 8B` |

校验自洽测试：4 条帧重算 SUM 与帧尾一致（D7/DF/AB/09 全 OK）。失配负例：把状态帧 PAYLOAD 任一字节翻转 1 位后重算得 `D6` ≠ 帧尾 `D7`，**可检出**。

### 9. 时序与带宽预算

- 状态帧 19 字节 × 10 bit = 190 bit ÷ 9600 bps = **19.79 ms/帧**；周期 100 ms → 上行占用 **19.8%**，余量充足。
- 命令帧 8 字节 = 8.33 ms，应答帧 7 字节 = 7.29 ms。
- 事件帧即时发送，允许与状态帧交错（帧边界由 `AA 55` + LEN 界定，交错不影响解析）。
- MCU 侧建议：发送用查询式即可（19.8% 占用），无需 DMA；接收用 UART 中断 + 环形缓冲。

### 10. 解析状态机与错误处理（三方共用）

1. 逐字节扫描找 `0xAA`，下一字节须为 `0x55`，否则继续扫描（天然抗丢失同步）。
2. 读 LEN：不在 `1..15` 内 → 回到步骤 1（不消费，从下一个字节重找 `0xAA`）。
3. 读 TYPE + PAYLOAD，等满 LEN 字节；超时（>50 ms 无新字节）→ 丢弃半帧，回步骤 1。
4. 算 SUM 比对：不等 → 丢弃，`CRC_ERR` 计数 +1，回步骤 1。
5. 方向位校验失败 → 同步骤 4 处理。
6. 上位机侧：状态帧 SEQ 出现跳号 → 记 `LOST_FRAMES`；重复 → 丢弃不更新界面。
7. 上位机侧：连续 500 ms 未收到任何合法上行帧 → 看板判"通信中断"，显示最后快照并置灰。

### 11. 本轮相对 baseline 的改动（必须让下游知道）

1. **`0x82 下行 ACK` 取消，改为 `0x03 上行命令应答帧`。** 原 baseline 把 ACK 标为"下行"方向有误：应答由设备发出，必属上行；`0x8x` 段整段保留给下行。是否使用 ACK：**使用**（强制，每命令一条）。
2. **状态帧新增 `SEQ(1)` 与 `MODE(1)`**（baseline 只有 DIO/CNT/CYC/TMP/PRS）。理由：§六 要"实时运行状态"需要 MODE；丢帧检测需要 SEQ。PAYLOAD 由 12 → 14 字节，仍在 LEN 上限内。
3. **PRS 单位二选一，锁定 0.1 kPa**（不选 mbar）。
4. **锁定传感器哨兵值** `TMP=0x7FFF` / `PRS=0xFFFF`，因传感器型号未定。
5. **明确 SB1 取反在固件内完成**、DIO 保留位规则、命令幂等与超时重发规则。

### 12. 各轮要做的事（引用本协议，不改字段）

- **R2 AD**：P3.0/P3.1 走 CH340/CP2102 到 USB 端子；LED_RUN/LED_ALARM 改接 P3.2/P3.3；温度/气压按"通用接口预留"（DS18B20 单总线占 1 脚 + I²C 预留 P1.6/P1.7 或 SDA/SCL 两脚，型号未定先留排针）。
- **R3 Proteus**：可用 Virtual Terminal 挂 P3.0/P3.1 直接看本协议字节流。
- **R4 上位机**：`pyserial` 按 §2/§10 实现解析器；四类数据按 §4/§5 映射。
- **R5 监控看板**：只读上位机推送，字段名与 §4/§5 一致，哨兵值不显示为 0。

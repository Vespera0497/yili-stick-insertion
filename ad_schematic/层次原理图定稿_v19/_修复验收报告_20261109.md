## 二、三个真正导致失败的坑（按定位顺序）

之前反复出现「打开是一片空白」，一直以为是新增的矩形 / 导线格式写错了。
用 7 个拆分变体做二分实验后发现，新对象本身是对的，问题出在**容器层**。

### 坑 1 · `FileHeader` 的 HEADER 帧被重建时丢掉

`.SchDoc` 的 `FileHeader` 流第一条**不是对象记录**，而是强制格式头：

```
|HEADER=Protel for Windows - Schematic Capture Binary File Version 5.0|Weight=81|MinorVersion=2|UniqueID=LBXIBPBR
```

分帧器因为「不以 `|RECORD=` 开头」把它跳过了，重建时整条丢失。
AD 读不到这个头会**静默打开一张空白图纸，连错误框都不弹**。
连「原样输出、一个对象都没改」的对照组也是空白，就是这条证据。

> 修复：分帧器保留所有非对象帧，原样回写。

### 坑 2 · `Weight` 没有随对象数更新

`HEADER` 里的 `Weight` 就是 **FileHeader 中的对象记录总数**。
核对了 12 个未经改动的原始文件，`Weight` 与对象数**无一例外精确相等**：

| 来源 | Weight = 对象数 |
|---|---|
| 学校 Main / Sub3 / Sub4 / Sub5 / Sub6 / 电机驱动 / 隔离部分 | 122 / 366 / 447 / 488 / 1516 / 925 / 651 |
| v19 部署前 P1～P5 | 90 / 175 / 134 / 166 / 81 |

只追加对象、不更新 `Weight`，AD 就只读取旧数量，
把新增的矩形、导线、Junction **全部截掉**——页面看起来毫无变化，也不报错。
这也解释了为什么 HEADER 修好后仍只有孤立引脚。

> 修复：重建结束前把 `Weight` 改写为「原对象数 + 新增对象数」，并写进自检护栏。

### 坑 3 · Wire 的 `UniqueID` 长度不合规

学校工程 3325 个 `UniqueID` **全部是 8 位 base36**；
`RECORD=27 Wire` 必须带，`RECORD=14/29` 必须不带。
旧生成器有个循环第一次就 `return` 的漏洞，Wire 的 ID 只有 1 个字符（如 `A`），
会让 AD 加载器报错。

> 修复：生成 8 位 ID（AAAAAAAA 起），并保证文件内不重复、不与已有 ID 冲突。

## 六、顺带记录的 AD 操作要点

- `Ctrl+O` 在 **Home Page** 上不会弹打开文件对话框；必须让某个原理图编辑器处于激活态，
  或把文档路径直接作为 `X2.EXE` 命令行参数传入（一次可传多个，最稳）。
- 用 `PostMessage` 给 `TGUIDocBarButton` 发鼠标消息**切不动**标签页，
  必须用真实鼠标点击；可用窗口标题变化确认切换是否生效。
- `ad_seq.kill_dialogs()` 里硬编码了旧进程号，对当前 AD 实例无效，
  排查界面卡住时不能依赖它。
